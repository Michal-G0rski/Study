# February 2027 — Stage 2, Microsoft Sentinel & KQL Begin

Month 5 of [the plan](../README.md). **15 h/week: 2.5 h/day, Monday to Saturday, Sunday off.**

Three clean weeks, 45 hours. February 2027 begins on a Monday. This is the first half of a six-week Sentinel/KQL block — the other three weeks are the start of [March](2027-03.md). Splitting it across two files is deliberate: one topic per week, not four KQL operator families crammed into four days the way the old plan did it.

**No personal Azure subscription this month, and none for the rest of the plan.** The Sentinel learning-path modules are read for the concepts (architecture, data model, rule and workbook design) — they are free, but they carry no hands-on Sentinel lab, so nothing here runs in a live Sentinel workspace. KQL is practised hands-on for free instead: in the [Log Analytics demo environment](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/log-analytics-tutorial) (real sample tables, a Microsoft account, read-only, nothing to bill), and later against your own data in a [free Azure Data Explorer cluster](https://dataexplorer.azure.com/freecluster) (no subscription, no card). Everything that has to persist — the detection library, custom rules — goes into [Wazuh](https://wazuh.com/), self-hosted, starting this month. The honest trade: the Sentinel product UI (analytics-rule wizard, workbooks, playbooks) is studied as concept, not operated in a live tenant — a deliberate gap, in exchange for a plan that cannot generate a surprise invoice. The KQL cheat sheet lives in Git with the rest of the portfolio.

## Sources in use this month

- [Microsoft Sentinel learning path](https://learn.microsoft.com/en-us/training/paths/sc-200-configure-azure-sentinel-environment/) — free, official Microsoft Learn modules (concept; read, not a live lab)
- [Must Learn KQL (Rod Trent)](https://github.com/rod-trent/MustLearnKQL) — the practical KQL reference
- [Log Analytics demo environment](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/log-analytics-tutorial) — free, real sample tables (`SecurityEvent`, `SigninLogs`…), where KQL syntax is practised hands-on. **It is read-only and holds only Microsoft's sample data — none of your attacks are in it**, so it is for learning operators, not for testing your detections.
- [free Azure Data Explorer cluster](https://dataexplorer.azure.com/freecluster) — no subscription, no card. **This is where your own data goes:** ingest January's attack datasets (Security-Datasets / EVTX-ATTACK-SAMPLES) here and your KQL detections have real 4768/4769/4662 events to fire on. The demo environment teaches the language; the ADX cluster is where the AD detections are actually validated.
- [Microsoft Applied Skills](https://learn.microsoft.com/en-us/credentials/browse/?credential_types=applied%20skills) — free, hands-on, browser-lab assessments (there are Sentinel and Defender-track ones). Bookmark now; they are the closest free thing to operating the real product, and they matter more in [May](2027-05.md).
- [LetsDefend](https://letsdefend.io/) — free blue-team labs (start alongside)
- [KC7](https://kc7cyber.com/) — free, browser-based KQL-on-a-security-story game; a fast way to log KQL reps for the [monthly skill check](README.md#standing-rules)
- [Wazuh](https://wazuh.com/) — self-hosted, open-source SIEM/XDR (OpenSearch-based), installed this month as the permanent home for every detection worth keeping. **The client agent enrolled below feeds host/Sysmon events; the DC-side AD attacks (4768/4769/4662) are not produced by a workstation agent — ingest January's datasets (or a real DC's logs) into Wazuh so those detections have events too.**

## Rules for a week that goes wrong

- The SIEM hours are protected. This block runs through mid-March; nothing later in the plan works without it.
- **Every KQL query is written by you, not pasted.** The cheat sheet is the proof.
- **No personal Azure resource is ever created this month.** Where the SC-200 syllabus needs a live Sentinel tenant, it is studied as concept from the modules and docs — an accepted gap; the hands-on hours go to KQL in the demo environment, Wazuh, and LetsDefend.
- If LetsDefend is slow, substitute with CyberDefenders or public alert sets — but do the triage writing.
