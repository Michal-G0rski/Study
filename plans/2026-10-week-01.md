# Week 1 — 5–11 October 2026

Stage 1, Foundations. First week of the plan in [README](../README.md).

**Budget:** 2.5 h/day, Monday to Saturday, Sunday off = 15 h.
Open this file, go to today's date, do the two blocks, tick the boxes. No decisions required.

> Why 6 × 2.5 h and not 5 × 3 h: a language is learned by frequency, not by session length, and the sixth day is what keeps the week from collapsing when one day goes wrong. If your schedule forces it, 5 × 3 h Monday–Friday is an acceptable swap — the weekly content is identical.

## Week 0 — setup (Thu 1 – Sun 4 October, ~2 h, one sitting)

Do this before Monday so that week 1 is not spent installing things.

- [ ] In NixOS-WSL, create `~/lab/` and put this `shell.nix` in it:
      ```nix
      { pkgs ? import <nixpkgs> {} }:
      pkgs.mkShell {
        packages = with pkgs; [ gcc clang gdb valgrind gnumake ];
      }
      ```
      Enter it with `nix-shell`. Keep the directory on the Linux disk, not under `/mnt/c` — file traversal there is three orders of magnitude slower.
- [ ] Verify: `gcc --version`, `gdb --version`, `valgrind --version` all answer.
- [ ] Compile a hello world with the flags you will use all year:
      `gcc -std=c17 -Wall -Wextra -Wpedantic -g -fsanitize=address,undefined hello.c -o hello`
- [ ] Create a **public** GitHub repo `low-level-lab`, `git init` in `~/lab`, first commit, push.
      Push works through the Windows `gh` credential bridge; `gh` as a command inside WSL would need its own `gh auth login`, which you do not need for this.
- [ ] Open [Modern C](https://gustedt.gitlabpages.inria.fr/modern-c/) and save the PDF somewhere you will actually open it.
- [ ] Pick the daily slot — the same hour every day — and put it in your calendar as a recurring block until the end of the year.

**Done when:** `git log` in `low-level-lab` shows one commit, and the sanitizer-instrumented hello world runs.

## Monday 5 October — hello, toolchain

- [ ] **A (100 min)** — [Modern C](https://gustedt.gitlabpages.inria.fr/modern-c/), ch. 1 *Getting started* and ch. 2 *The principal structure of a program*. Type every example by hand and compile it. Do not copy-paste: the point of this week is that your fingers learn the syntax, not that your eyes recognise it.
- [ ] **B (50 min)** — [Missing Semester, lecture 1 — the shell](https://missing.csail.mit.edu/2020/course-shell/), including the exercises at the bottom.
- [ ] **Commit** `day01/` with every example you compiled.

## Tuesday 6 October — control flow

- [ ] **A (100 min)** — Modern C ch. 3 *Everything is about control*, first half: `if`, `switch`, `for`, `while`, `do`. Attempt every "challenge" you can; skip the ones needing later chapters and write down which.
- [ ] **B (50 min)** — [Missing Semester, lecture 2 — shell tools and scripting](https://missing.csail.mit.edu/2020/shell-tools/).
- [ ] **Commit** a shell script that compiles every `.c` in a directory with the strict flag set. You will use this every day for months, so write it properly once.

## Wednesday 7 October — control flow, part two

- [ ] **A (100 min)** — finish Modern C ch. 3. Then, book closed: write a program that takes numbers as command-line arguments and prints their minimum, maximum and mean. Handle zero arguments and non-numeric input without crashing.
- [ ] **B (50 min)** — [Missing Semester, lecture 6 — version control](https://missing.csail.mit.edu/2020/version-control/). Out of order on purpose: you are committing daily from now on, so you need git's data model now, not in week 6.
- [ ] **Commit** a `Makefile` that replaces yesterday's script.

## Thursday 8 October — expressing computations

- [ ] **A (100 min)** — Modern C ch. 4 *Expressing computations*. Pay attention to the parts that will bite you later: integer promotion, truncating division, `%` with negative operands, and what the standard does *not* promise.
- [ ] **B (50 min)** — write five short programs that each trigger one undefined or implementation-defined behaviour you just read about: signed overflow, shift by more than the width, uninitialised read, out-of-bounds array access, `char` signedness. Run each one twice — with and without `-fsanitize=undefined` — and record both outputs.
- [ ] **Commit** `ub-demos/` with a ten-line note on what each program did. This is the first real material for your blog; do not skip the note.

## Friday 9 October — values and data

- [ ] **A (100 min)** — Modern C ch. 5 *Basic values and data*: the type zoo, `size_t`, the fixed-width types in `<stdint.h>`, when a cast is honest and when it hides a bug.
- [ ] **B (50 min)** — [Missing Semester, lecture 7 — debugging and profiling](https://missing.csail.mit.edu/2020/debugging-profiling/), gdb section first. In gdb: set a breakpoint, step, inspect a local, print a struct, and dump raw memory with `x/16xb`.
- [ ] **Commit** a gdb cheat sheet of ten commands, written in your own words. You will reopen this file at the Bomb Lab in Stage 2.

## Saturday 10 October — consolidate

- [ ] **A (100 min)** — pick the two exercises from this week you guessed at or got wrong. Redo them with the book closed. Then read [Beej's Guide to C](https://beej.us/guide/bgc/html/split/), ch. 1–3, fast — it is the same material explained differently, which is where it stops sliding off.
- [ ] **B (50 min)** — weekly review. Write the answers down, do not just think them:
      1. What could I not explain this week without looking it up?
      2. Which compiler warning did I see and not understand?
      3. What carries into week 2?
- [ ] **Commit and push** `week01/review.md`.

## Sunday 11 October — off

Off means off. The schedule has a rest day because 15 hours a week for 18 months only works if it is sustainable.

## When the week goes wrong

Rules decided now, so you are not negotiating with yourself at 21:00 on a Wednesday.

- **Never skip block A two days running.** C is the one prerequisite in this plan with no workaround.
- **Drop block B first.** The toolchain material is catch-up-able; the language is not.
- **A missed day is not a failed week.** Move it to Sunday — at most once a month.
- **Do not get ahead.** Finishing Thursday's chapter on Tuesday means you read it instead of doing it.
